# LOB Layer Charter

이 문서는 `@iyulab/enterprise` 가 **무엇을 소유하고 무엇을 소유하지 않는가**를 정한다.
카탈로그를 늘리기 전에 이 문서를 먼저 읽는다 — 여기 적힌 등급과 계약이 *"만들어도 되는가"*
를 가른다.

---

## 1. 계층

```
L3  앱 템플릿    ListPage · MasterDetailPage · DashboardPage        ← 아직 없음
L2  LOB 패턴     FormSection · FormRow · …                          ← enterprise 가 소유
L1  컴포넌트     @iyulab/components · flex-table · u-widgets
L0  토큰         역할 토큰 · 스케일 토큰 (components 가 소유)
```

- **`enterprise` 는 L2 를 소유한다.** L3 는 **수요가 모인 뒤** 승격한다(§3 등급 참조).
- **의존 방향은 한 방향뿐이다**: `enterprise → components · flex-table`. 역방향은 없다.
  소비앱은 `enterprise` 만 알아도 화면을 만들 수 있어야 한다.

### ★ 프레임워크 전제 — 표류시키지 않는다

> **L0·L1 은 프레임워크 중립이다. L2·L3 는 React 를 전제한다.**

L1(`components`)은 Lit 웹 컴포넌트라 어느 프레임워크에서든 쓰인다. 그러나 L2 는 이미
`.tsx` 이고, LOB 패턴 계층을 여기에 쌓는다는 것은 **이 계층을 React 전용으로 확정한다**는
뜻이다. 이 문장을 적어 두지 않으면 다른 프레임워크의 소비자가 나타났을 때 **아무도
결정하지 않은 채 갈라진다** — 이 계층이 막으려는 실패가 정확히 그 형태다.

Lit/Vue 소비자는 **L1 을 직접 쓴다.** L2 를 프레임워크 중립으로 다시 만드는 것은
이 헌장의 개정 사항이지 구현 과제가 아니다.

---

## 2. 오버라이드 계약 — **1급 조항**

| 층 | 소비자가 바꾸는 방법 | 금지 |
|---|---|---|
| **L2** | **slot(children) 치환 + prop** — 구조는 두고 내용만 바꾼다 | 내부 DOM 선택자 침투 |
| **L3** | 구성 객체 + slot | 템플릿 내부 분기 |

> ★**오버라이드 경로가 없는 패턴은 이 계층에 들어올 수 없다.**

이유는 실패 형태가 알려져 있기 때문이다. L2/L3 는 *"조금 다르면 통째로 갈아엎게 되는"*
쪽으로 가기 쉽고, 그러면 소비앱은 **패턴을 쓰기 전보다 나쁜 상태**가 된다 — 갈아엎은
사본을 자기 코드베이스에 갖게 되는데, 그것은 애초에 자기가 소유하던 코드보다 나을 것이
없으면서 업스트림과의 연결만 끊긴 상태다.

### 2-1. 스타일 오버라이드는 L1 의 답을 상속한다

L2 는 L1 위에 앉으므로 **두 층이 다른 오버라이드 철학을 가지면 안 된다.** `components`
1.12.0 이 같은 질문에 이미 답했고, 이 헌장은 그 셋을 그대로 상속한다:

| 질문 | 답 |
|---|---|
| 스타일을 바꾸는 **정규 경로**는 | **CSS 커스텀 프로퍼티.** `::part` 는 열어 두되 1순위가 아니며, 호스트 요소 직접 오버라이드는 **신뢰할 수 없다**(소비앱의 CSS 리셋에 지워진다) |
| 경로를 **문서화하지 않으면** | 소비자가 무효인 우회를 수년간 유지한다. ⇒ 커스텀 프로퍼티는 **선언하고 문서화한다** |
| 내부 구현 슬롯과 공개 훅을 어떻게 가르나 | 내부 슬롯은 **이유와 함께 명시 목록에 등재**한다 |

**따라서 L2 컴포넌트에 인라인 `style` 로 굳힌 값을 두지 않는다.** 인라인 스타일은
소비자 CSS 가 이길 수 없어(`!important` 외) 위 계약을 원천적으로 무효화한다. 값은
토큰으로 읽고, `className`·`style` prop 을 받아 병합한다.

### 2-2. 색은 **역할 토큰**으로 읽는다

팔레트(`--u-blue-600`)를 직접 읽지 않는다. 팔레트는 **이름이 곧 값의 약속**이라,
소비자가 브랜드를 맞추려고 그것을 덮으면 *진짜 파랑*이 필요한 곳까지 함께 오염된다.
역할 토큰(`--u-primary-color` 등)을 읽으면 재브랜딩이 한 줄로 끝난다.

## 3. 카탈로그 — 등급이 곧 착수 허가다

| 등급 | 뜻 | 착수 |
|---|---|---|
| ★★ **실측** | 둘 이상의 소비자가 **같은 골격을 실제로 반복**하는 것이 관측됨 | 가능 |
| ★ **실측(부분)** | 반복은 관측되나 골격이 아직 한 형태로 수렴하지 않음 | 설계 선행 |
| ○ **요구** | 있으면 좋겠다는 요청만 있고 반복 실측이 없음 | ❌ **만들지 않는다** |

> ★**"요구" 등급을 만들지 않는다**는 것이 이 표의 핵심이다. 실측 없이 만든 패턴은
> *"만들어 두고 아무도 쓰지 않는"* 형태로 끝나고, 그 뒤로는 지우기도 어려워진다.

### L0.5 — 하우스 값은 이 패키지에 없다 → `@iyulab/house-style`

하우스 값(타입 스케일·반경·엘리베이션·중립 램프·상태 색)과 그 위의 컴포넌트 레시피·LOB 레이아웃 패턴은
**`@iyulab/house-style`** 이 소유한다 — CSS 전용 테마 패키지이며 `@layer iyu.house` 에 산다
(기본값 `iyu.base` < 하우스 < 앱). 종전 `styles/preset.css` 는 그쪽으로 흡수됐다.

이 패키지(L2)는 **React 패턴의 구조와 동작**만 소유한다. 패턴이 그리는 외형은 토큰을 읽으므로
하우스 테마를 로드한 앱에서는 하우스 외형을, 로드하지 않은 앱에서는 중립 기본값을 받는다.

### 현재 카탈로그

| 패턴 | 등급 | 상태 |
|---|---|---|
| `FormSection` · `FormRow` | ★★ 실측 | **제공 중** |
| ListPage 키트(목록 골격) | ★★ 실측 | ⏸ 미착수 — 아래 승격 조건 참조 |
| SearchSection(검색·기간·필터) | ★ 실측(부분) | ⏸ 미착수 |
| DataCard / 카드 목록 | ★ 실측(부분) | ⏸ 미착수 |
| ~~EmptyState~~ | — | ➡ **`@iyulab/modern-app` 로 이관**(2026-08-03) — 아래 |
| ErrorState · Skeleton | ★ 실측(부분) | ⏸ 미착수 |
| Banner(공지·경고) | ○ 요구 | ❌ 만들지 않는다 |
| Widget(대시보드) | ○ 요구 | ❌ 만들지 않는다 |
| L3 템플릿 | ○ 요구 | ❌ 만들지 않는다 — 마지막 |

> ➡**`EmptyState` 이관 근거(2026-08-03)**: 빈 상태는 **프레임워크 중립**이 맞다. 이 계층의 L2 는
> **React 전용**인데(§ 프레임워크 전제), 빈 상태는 목록·검색 결과가 있는 화면이면 어디서나
> 필요하고 Lit 커스텀 엘리먼트로 내면 React·Vue·바닐라가 모두 태그로 쓴다.
> ⇒ `@iyulab/modern-app` 이 `u-empty-state` 로 소유한다(그쪽 `docs/lob-primitives.md`).
> ★**같은 표면을 두 패키지가 각각 만들면 소비자가 둘 중 무엇을 쓸지 매번 고르게 된다** —
> 그 비용은 만드는 쪽이 아니라 쓰는 쪽이 낸다. `ErrorState`·`Skeleton` 도 같은 판단이
> 적용될 수 있으나, 착수 시점에 다시 본다(지금 옮기면 실측 없이 자리만 옮기는 것이다).

### 3-1. ★★ 등급이어도 자동 착수는 아니다 — 승격 조건

등급은 *"요구가 실재한다"* 는 근거일 뿐 착수 허가가 아니다. 판정 기준은 **요구한 소비자의
수가 아니라** 그 패턴이 이 계층에 맞는가와 설계가 섰는가다. ★★ 실측 패턴이 구현으로
승격하려면:

1. **이 계층이 마땅히 할 일**이다 — 골격이 LOB 화면 일반의 것이고(§4 의 소비자 도메인
   개념이 아니다), 계층이 없으면 소비앱마다 같은 재구현이 생긴다. 요구가 한 곳에서
   왔어도 같은 근본 원인에 부딪힐 다른 소비자의 표본으로 읽는다.
2. 그 골격이 **한 형태로 수렴**한다. 같은 요구에 서로 다른 구현이 나와 있다면 그것은
   *"공통 골격이 정해졌다"* 가 아니라 *"아직 정해지지 않았다"* 의 증거다 — 갈라지게 만든
   원인(예: 아래 계층의 어휘 차이)을 먼저 푼다.
3. **§2 의 오버라이드 계약을 만족하는 설계**가 먼저 나온다.

⇒ 2·3 이 서기 전에는 미착수가 맞다. 그것은 수요가 모이기를 기다리는 것이 아니라 **설계가
정해지기를 기다리는 것**이고, 그동안 막는 원인을 푸는 일은 지금 할 수 있다.
요구한 쪽이 하나라는 사실은 보류 사유가 아니다.

## 4. 이 계층이 소유하지 않는 것

- **소비자 도메인 개념** — 특정 업무 엔티티·권한 문자열·업무 흐름. 범용어로 포장해도
  마찬가지다(`prefix`·`originLabel` 같은 이름 뒤에 도메인 의미가 숨어 들어간다).
- **특정 팔레트·레이아웃 취향** — 계층은 **그릇**이지 디자인이 아니다.
- **앱의 IPC/wire 프로토콜** — 앱이 자유롭게 확장한다. 라이브러리 타입을 앱의 wire
  타입으로 재사용하지 않는다.

도메인 변환은 **소비앱의 어댑터 층**에 산다. 그 경계가 이 계층이 여러 소비자에게
쓸모 있는 상태로 남는 유일한 이유다.

| L2 컴포넌트가 인라인 스타일로 값을 굳히지 않는다 | ✅ 0.5.0 에서 해소 |
| L2 가 팔레트를 직접 읽지 않는다 | ✅ 0.5.0 에서 해소 |
| 같은 종류의 화면이 소비자들 사이에서 같은 코드 경로를 탄다 | ⏸ 카탈로그 승격 이후 |
| 패턴 하나만 다르게 하고 싶을 때 slot 1개로 끝난다 | ⏸ 카탈로그 승격 이후 |
